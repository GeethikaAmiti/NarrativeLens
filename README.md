# NarrativeLens

**“One event. Many lenses.”**

NarrativeLens is a time-aligned cross-source news-coverage analysis dashboard.
It is designed for readers who want to understand a current-affairs event and
then compare how different publishers foreground different parts of that event.

It is **not** a chatbot, truth scorer, fake-news detector, sentiment analyser,
or political-bias classifier.

## What the user sees

### The Core — understand the event

The Core begins with a **six-point Situation in Brief**.

The briefing is not generated by an external LLM/API. Each point is a cleaned
sentence retrieved from one of the selected event-aligned articles. MiniLM
semantic similarity is used to rank event relevance, reduce redundancy, and
measure whether a point is echoed across multiple sources.

The UI explicitly distinguishes:

- information semantically echoed across multiple selected sources;
- useful context supplied by only one selected report.

Below the briefing, the stricter Shared Developments section retains the
three-source consensus rule and displays source support plus cosine similarity.

### The Lenses — compare how the event is told

The Lenses no longer depend on six generic fixed categories as their primary
output.

Instead, NarrativeLens derives **event-specific coverage facets** from the
selected articles themselves:

1. clean and embed event-relevant sentences from every selected article;
2. cluster semantically related sentences;
3. give each cluster a compact event-specific label using TF-IDF n-grams and
   extracted proper-name context;
4. measure how much of each article's retained event-relevant text falls into
   each facet;
5. show exact article sentences as evidence for the source's main and
   secondary emphasis;
6. identify facets that are prominent in multiple other selected reports but
   comparatively less visible in the current article.

A “coverage angle” therefore means **observable textual emphasis in the
selected article**, not inferred editorial motive.

“Less visible” means only that the facet was not strongly represented in the
specific extracted article text being compared. It does not prove that the
publisher never covered it elsewhere, intentionally omitted it, or that the
underlying event did or did not occur.

### The Visual Lens — compare visual representation

The existing visual pipeline is preserved:

- deep-image embeddings;
- cosine similarity;
- neutral visual groups;
- controlled visible-content descriptors;
- pairwise visual-similarity matrix.

The dashboard keeps model implementation names mostly in methodology rather
than normal user-facing prose.

## Pipeline

```text
query + time intent
-> retrieve publisher articles
-> time filtering
-> query relevance
-> same-event cohesion
-> source diversity
-> best 4–6 comparable reports
   |
   +-> Situation in Brief
   +-> Shared claim clusters
   +-> Event-specific coverage facets + article evidence
   +-> Visual similarity/content comparison
```

## Models and techniques

- Sentence embeddings: `all-MiniLM-L6-v2`
- Similarity: cosine similarity
- Event-specific text facets: MiniLM embeddings + greedy semantic clustering
- Facet labels: TF-IDF n-grams + proper-name extraction
- Visual similarity: pretrained MobileNetV2 embeddings
- Visible-image descriptors: zero-shot CLIP worker with controlled prompts

No runtime generative AI API is required.

## Important methodological limits

NarrativeLens compares selected article text. It does not know everything that
happened at an event, everything a publisher has ever reported, or why an
editor made a particular choice.

Social-media footage, eyewitness accounts, video, and reports outside the
selected article set can contain additional information. The system should
therefore be read as:

> “How do these selected articles represent the event?”

not:

> “What is the complete objective truth of the event?”
